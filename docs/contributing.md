# Contributing

## Inside CHEER

- New code goes in a CHEER-Hub repository started from the Python templates (bronze for scripts, silver for
  packages, gold for released tools). Ask Mohammad Askari for access.
- New datasets go to DesignSafe PRJ-4392 (internal) or a published DesignSafe project (public), and get a row
  in the Knowledge Object Inventory before they are used in an analysis.
- Document each object with the metadata template: purpose, inputs, outputs, version, contact, status.
- Read the [Markdown and Git tutorial](https://cheer-hub.github.io/MD-Git-Essentials/) if Git is new to you.

## Outside CHEER  <span class="todo">to be confirmed</span>

Open-source contribution will be possible once the licence is settled (see [Governance](governance.md)).
The intended model:

- **Issues and pull requests** on the relevant repository, reviewed by that module's maintainer.
- **Extensions** (a new damage model, a new region, a new decision model) live in your own repository, started from
  the *STARR extension template*, and are listed on the Community extensions page with the STARR version they target
  and a DOI (Zenodo).
- **Code of conduct**: the Contributor Covenant, adopted for all CHEER-Hub repositories.

## Authorship

Use of CHEER code and data in publications follows the CHEER Authorship Guide (CoPe Drive, Knowledge Framework).
