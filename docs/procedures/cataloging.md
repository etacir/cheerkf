
# Cataloging procedures

*Original page was a stub ("needs to be created", 2024). Rewritten September 2026; <span class="todo">to be confirmed</span>.*

CHEER keeps two catalogs.

**Code and data: the Knowledge Object Inventory.** Every model, dataset and code object gets a row in the
*CHEER Knowledge Object Inventory* spreadsheet (CoPe Drive, Knowledge Framework / STARR to KF) when it is first
shared with anyone outside its author's group, and a new row for every version after that. The row records the
object ID, name, version, what it is, what changed from the previous version, where it is stored, who to ask, and its
status (development, final, superseded, abandoned, with the reason). The [Catalog](../catalog.md) page of this site is
generated from that spreadsheet.

**Publications and presentations: Zotero.** Papers, posters, presentations and other outputs with a DOI are recorded
in the CHEER Zotero library so they can be reported to NSF and listed on the [Community](../community.md) page.
Procedure and library location: <span class="todo">to be confirmed</span> (Robin Carlson and Lindsey were named as contacts in 2024).

**When to catalog**

- Before a dataset or code is used in a paper or an analysis by someone other than its author.
- When a version is published (DesignSafe DOI, Zenodo DOI) or presented.
- When an error is found and fixed: new row, old row marked superseded.

See also the [Data publishing checklist](data-publishing-checklist.md) and [Versions and compatibility](../versions.md).
