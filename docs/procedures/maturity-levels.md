
# Research readiness levels

*From the 2024 "Managing Science-y Stuff" page, whose Level 0-3 headings were never filled in, and the July 2024 kf\*
Workflow Diagrams. The definitions below are proposed; <span class="todo">to be confirmed</span>.*

Each research thrust manages its own outputs in line with the Hub's knowledge-management strategy. Data and code
move up a readiness ladder; the higher the level, the more curation, metadata and documentation are expected. The
aspiration is FAIR data (findable, accessible, interoperable, reusable). Partly FAIR may be good enough.

| Level | Meaning | Minimum requirements |
|---|---|---|
| **0 Internal** | Working material inside one group | Code under version control (a CHEER-Hub repository, may be private); data in the group's DesignSafe or Drive folder; a README naming the author and purpose |
| **1 Shareable** | Used by other CHEER groups | Row in the Knowledge Object Inventory; version name; metadata file from the [template](metadata-template.md); data in DesignSafe PRJ-4392 with the file-naming standard; repository README with inputs, outputs and how to run |
| **2 Published** | Available to anyone | DesignSafe or Zenodo DOI; licence; the [Data publishing checklist](data-publishing-checklist.md) completed and reviewed by the kf* manager; citation file; listed on this site's [Catalog](../catalog.md) |

**Code management.** Model, analysis and visualization code is version-managed on GitHub in the CHEER-Hub
organization, whatever the language; see [GitHub procedures](github.md).

**File management.** Collaborative documents live in the CoPe shared Google Drive.
